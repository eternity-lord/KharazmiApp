## ۱) مشکل: سه مسیر حذف کلاس، سه معنای متفاوت

در سیستم سه راه برای حذف/آرشیو کلاس وجود دارد. دو مسیر از `_apply_class_deletion` استفاده می‌کردند ولی مسیر سوم (همان دکمهٔ «رد کلاس» در اپ — صفحهٔ کلاس‌های در انتظار تایید) کد جداگانه‌ای داشت:

```python
# وضعیت قبلی — admin.py
c = db.query(Course).filter(Course.id == course_id).first()
enrollments = db.query(Enrollment).filter(Enrollment.course_id == c.id).all()
for en in enrollments:
    perform_delete_enrollment(en, db)        # قبض‌ها/کیف پول: بله
c.is_deleted = True                          # کلاس: بله
# ❌ جلسات آرشیو نمی‌شدند
# ❌ هیچ رکورد حذفی (تاریخ/عامل/snapshot) ثبت نمی‌شد
```

**دو پیامد واقعی (اثبات‌شده با تست رگرسیون):**

| پیامد | جزئیات |
|---|---|
| **طلب معلم از کلاس ناموجود باز می‌ماند** | جلسات کلاس حذف‌شده فعال می‌ماندند ⇒ در «طلب تسویه‌نشده‌ی معلم» و قابل تسویه ⇒ پرداخت برای کلاسی که در سیستم وجود ندارد |
| **رد پای حسابرسی گم می‌شد** | هیچ `ClassDeletionRequest` ساخته نمی‌شد ⇒ در نمای آرشیو، `deleted_at` خالی و عامل حذف نامعلوم (کلاس‌های legacy با `deleted_at=""` از همین جنس‌اند) |

## ۵) ریسک‌ها و محدودیت‌های باقی‌مانده

1. **کلاس‌هایی که پیش‌تر با این مسیر حذف شده‌اند اصلاح نمی‌شوند** (جلساتشان هنوز فعال و طلب معلم باز است). داده‌ی موجود تغییر نکرد (طبق قانون). SQL سنجش (فقط خواندن) برای اجرای دستی:
   ```sql
   -- کلاس‌های آرشیوشده‌ای که جلسه‌ی فعال دارند (طلب باز از کلاس حذف‌شده)
   SELECT c.id, c.title, c.code, COUNT(s.id) AS active_sessions
   FROM courses c JOIN session_logs s ON s.course_id = c.id AND s.is_deleted = FALSE
   WHERE c.is_deleted = TRUE GROUP BY c.id ORDER BY c.id;
   ```
   در DB فعلی `courses` فقط یک ردیف و `is_deleted=false` است ⇒ موردی وجود ندارد. اگر روی DB تولیدی خروجی داشت، با تأیید صریح شما یک تسک داده‌ای برای هم‌سوسازی انجام می‌شود (الان دست نزدم).
2. **تفاوت کوچک عمدی:** مسیر سوم فقط ثبت‌نام‌های **فعال** را پردازش می‌کند (قبلاً همه را — ولی `perform_delete_enrollment` خودش idempotent است، پس اثر عملی یکسان است).
3. **کامپایل Kotlin بررسی نشد** — تغییر سمت اپ نداشتیم؛ امضای API و متن پاسخ دست‌نخورده است (اپ `PendingClassesActivity` با `SimpleResponse` کار می‌کند).
