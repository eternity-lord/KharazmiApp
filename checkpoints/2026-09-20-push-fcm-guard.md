## ۶) ریسک‌ها و محدودیت‌های باقی‌مانده

1. **API قدیمی FCM (`fcm/send`)**: پیاده‌سازی فعلی از سرور-کی legacy استفاده می‌کند که گوگل آن را منسوخ کرده است (برای اپ‌های جدید Firebase Cloud Messaging HTTP v1 توصیه می‌شود و نیازمند service-account/OAuth2 است). ساختار ماژول طوری نوشته شده که تعویض پروتکل فقط با تغییر `_default_sender` انجام شود (بدون تغییر در ۲۱ نقطهٔ فراخوانی).
2. **ارسال همگام (synchronous) داخل مسیر درخواست**: با timeout کوتاه (۵ ثانیه) و غیرکشنده؛ اگر روزی حجم اعلان بالا رفت، باید به یک صف/worker پس‌زمینه منتقل شود (worker پس‌زمینهٔ پروژه الگوی موجودی دارد).
3. **بدون اعتبارنامه، Push خاموش است**: این عمدی است (تصمیم C2)؛ تا وقتی کلید روی سرور تنظیم نشود، اعلان‌ها فقط درون‌برنامه‌ای هستند.
4. **پیکربندی سمت اپ (Firebase) بررسی نشد** — محدودیت محیط (بدون Gradle/SDK)؛ اگر اپ توکن Firebase نسازد، `device_tokens` خالی می‌ماند و Push ارسال نمی‌شود (بدون خطا).
5. **فقط توکن‌های دقیقاً مطابق نقش+کاربر** ارسال می‌شوند (همان قرارداد قبلی فیلتر) — رفتار تغییر نکرده است.
