## ۱) مشکل و ریشه

دو اندپوینت که پورتال دانش‌آموز/ولی را تغذیه می‌کنند، لیست اعلان را **هاردکد** برمی‌گرداندند:

```python
# routers/students.py  → GET /students/my_profile   (پورتال دانش‌آموز)
# routers/parent.py    → GET /parent/child_profile  (پورتال ولی)
notifications_list = [
    {"title": "اطلاعیه شروع ترم تحصیلی جدید", ..., "date": "۱۴۰۵/۰۶/۰۱"},
    {"title": "تعطیلی موقت به علت سرما",       ..., "date": "۱۴۰۵/۰۶/۰۲"}
]
```

پیامدها برای آموزشگاه:

1. **هر ولی/دانش‌آموز — مستقل از واقعیت — دو پیام ساختگی می‌دید** (شروع ترم، تعطیلی به‌خاطر سرما) با تاریخ‌های ثابت. یعنی پورتال «اطلاعیه» را نمایش می‌داد که هیچ ربطی به آموزشگاه نداشت.
2. مهم‌تر: **اعلان‌های واقعی هرگز به پورتال نمی‌رسید.** سیستم برای ولی و دانش‌آموز اعلان واقعی می‌سازد (پرداخت آنلاین فرزند، یادآوری قسط معوق، غیبت، آزمون، پیام) و در جدول `notifications` ذخیره می‌کند؛ ولی پورتال آنها را نشان نمی‌داد ⇒ **ولی از بدهی/غیبت فرزندش بی‌خبر می‌ماند** و کارکرد اصلی اعلان بی‌اثر می‌شد.
3. اپ اندروید (`ParentPortalActivity.kt` → دکمهٔ «اعلان‌ها» → `ParentNotificationItem(title, body, date)`) همان داده را مصرف می‌کند، پس کاربر نهایی مستقیماً پیام جعلی می‌دید.

## ۲) رفتار قبل و بعد

| موضوع | قبل | بعد |
|---|---|---|
| منبع اعلان در پورتال | دو رکورد ثابت در کد | جدول واقعی `notifications` (همان قرارداد اندپوینت `/notifications`) |
| کلید انتخاب رکورد | — | `recipient_user_id` (فضای `User.id` کاربر سایه) + `recipient_role` **کانونیکال** (`resolve_notification_role`) |
| ترتیب | جعلی | جدیدترین اول (`created_at DESC NULLS LAST`, سپس `id DESC`) |
| سقف تعداد | ۲ رکورد ثابت | ۵۰ اعلان جدیدترین (جلوگیری از پاسخ سنگین) |
| `created_at` NULL (رکورد legacy) | — | `date = ""` (رشته، هرگز `null`) — مدل اندروید `String` غیر-null |
| نشتی بین کاربران | — | تست‌شده: اعلان ولی دیگر / دانش‌آموز دیگر / نقش دیگر **دیده نمی‌شود** |
| مسیر/قرارداد پاسخ | `[...]` با کلیدهای `title/body/date` | همان + `id/type/is_read` (افزودنی، سازگار با اپ فعلی) |

**نکتهٔ طراحی:** مسیر HTTP برای «نشست ولی بدون لینک فرزند» همان ۴۰۴ قبلی می‌ماند (`get_session_parent`)؛ شاخهٔ دفاعیِ نبود رکورد کاربر، داخل helper و در سطح تست واحد سنجیده می‌شود.
