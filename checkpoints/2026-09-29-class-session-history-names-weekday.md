# تب «تاریخچه جلسات» — نامِ حاضر/غایب‌ها + روزِ هفته (اسکرین‌شات دوم)

اسکرین‌شات کاربر: کلاس ۱۰۰۰۰۲ → تب «تاریخچه جلسات» → هر جلسه فقط «✅ حاضرین: N نفر / ❌ غایبین: M نفر» را نشان می‌داد؛ نه اسم کسی بود و نه روزِ هفته.

## خلاصهٔ یک‌خطی
هر جلسه حالا **نامِ شاگردانِ حاضر و غایب** را می‌نویسد («فلان دانش‌آموز حاضر، فلان دانش‌آموز غایب»)، کنارِ تاریخ **روزِ هفتهٔ فارسی** را می‌آورد و علاوه بر آن یک خطِ جمعِ دوره، هزینهٔ هر جلسه و ساعتِ جلسه هم اضافه شده است. سرور هیچ عددی را عوض نکرد؛ فقط شکلِ گزارش کامل‌تر شد (همهٔ فیلدهای جدید پیش‌فرض دارند ⇒ پاسخ/کش قدیمی چیزی را نمی‌شکند).

## آنچه خواسته شده بود
| خواسته | وضعیت |
|---|---|
| نوشتن نامِ شاگردانِ حاضر/غایب به‌جای فقط تعداد | ✅ |
| روزِ هفتهٔ فارسی کنارِ تاریخ هر جلسه | ✅ |
| اعمال برای «تاریخچه جلسات» همهٔ کلاس‌ها (نه فقط این کلاس) | ✅ (موتور مشترک `/classes/{id}/full_report`) |

## بهبودهایی که اجازه داشتیم بدون پرسیدن اضافه کنیم
کاربر گفته بود هر بهبودی که برای این قسمت بهتر می‌دانیم مستقیم اضافه کنیم:
- خطِ جمعِ کلِ دوره بالای لیست: «📊 جمع دوره: N جلسه • ✅ حاضر X نفر • ❌ غایب Y نفر».
- هزینهٔ هر جلسه («💰 هزینهٔ این جلسه: … تومان (هر شاگرد: … تومان)») و ساعتِ جلسه («⏰ ساعت: start تا end») — فقط وقتی داده دارد.
- برچسبِ «(با تأخیر)» برای Present/Late و «(موجه)» برای غیبتِ موجه، کنارِ نام هر نفر.
- ترتیبِ جلسات صریحاً بر اساس `id` (ترتیب ثبت) شد تا شمارهٔ «جلسه ۱، ۲، …» تثبیت شود.
- نامِ خالی/شاگرد حذف‌شده ⇒ «نامشخص» یا سکوت (خطِ خالی چاپ نمی‌شود).

## سمت سرور (Kharazmi_Server)
- `schemas.py`:
  - `ClassSessionStudent` جدید: `student_id`, `name`, `student_code`, `status` (Present/Late/Absent), `excused`.
  - `ClassSessionHistory` گسترش یافت: `session_id`, `session_code`, `weekday`, `present_students`, `absent_students`, `total_cost`, `cost_per_student`, `start_time`, `end_time` — همه با مقدار پیش‌فرض (سازگاری با کلاینت/کش قدیمی). کلیدهای قبلی `date`/`present_count`/`absent_count` دست‌نخورده‌اند.
- `routers/classes.py` (`get_class_full_report`):
  - جلسات با `order_by(SessionLog.id.asc())` و بدون ردیف‌های آرشیوی (`is_deleted == False`) — مثل قبل.
  - برای هر جلسه یک کوئری `Attendance + Student` (outerjoin) به‌جای دو `count` جدا؛ Present/Late ⇒ لیست حاضرین، Absent ⇒ لیست غایبین، وضعیت‌های ناشناسِ legacy هیچ‌کدام (همان رفتار قبلیِ شمارش).
  - شمارش‌ها از روی همان لیست‌ها ساخته می‌شوند ⇒ «حاضرین: ۲ نفر» هرگز با تعداد نام‌ها ناسازگار نمی‌شود.
  - نام‌ها با `display_name(student, "نامشخص")` (ضدِ نامِ NULL در رکوردهای قدیمی).
  - روزِ هفته از `today_summary.parse_project_date` + `PERSIAN_DAY_NAMES` (همان تقویمِ مرکزیِ بقیهٔ اپ).
  - `total_cost` = جمع ذخیره‌شدهٔ سهم‌ها/جریمه‌های همان جلسه (`final_teacher_cost` + `final_institute_share` + `absent_penalty_teacher` + `absent_penalty_institute`) — فقط خواندنی؛ هیچ مالی‌ای نوشته نمی‌شود.
- `routers/students.py`: چهار کلاسِ تکراریِ `ClassReportInfo` / `ClassStudentData` / `ClassSessionHistory` / `FullClassReport` که فقط سایهٔ `schemas.py` بودند (هیچ روتی این‌جا از آن‌ها استفاده نمی‌کرد) حذف شدند تا شکلِ پاسخ یک منبعِ حقیقت داشته باشد.

## سمت اپ (KharazmiAdmin)
- `ClassDetailActivity.kt`: مدلِ Kotlin به همان شکل بالا گسترش یافت (همه پیش‌فرض‌دار: `emptyList()`/`""`/`0` ⇒ کشِ قدیمی صفحه را نمی‌شکند). رندرِ تب دوم:
  - «جلسه %s: %s (%s)» با روزِ هفته (اگر پاسخ قدیمی `weekday` نداشت، محلی از تاریخ حساب می‌شود).
  - زیر «✅ حاضرین: N نفر» نامِ تک‌تکِ حاضرین، و زیر «❌ غایبین: M نفر» نامِ غایبین (هر نفر یک خط).
- `JalaliUtils.kt`: تابع `persianWeekdayName(date)` (شنبه..جمعه؛ برای ورودیِ نامعتبر رشتهٔ خالی).
- `values/strings.xml`: هفت رشتهٔ جدید (`cdetail_hist_row_weekday`, `_summary`, `_student_row`, `_late_tag`, `_excused_tag`, `_cost`, `_time`).
